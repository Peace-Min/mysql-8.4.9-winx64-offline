========================================================
 수행과제 캘린더 — 과제 DB 폐쇄망 테스트
========================================================

[전제] 이 PC에 MySQL 8.4 서버가 설치·실행 중이어야 합니다.
       (아직이면 이 저장소 루트의 setup.cmd 로 먼저 설치)

[이 테스트의 구성]
   서버 DB = 이 PC (localhost)  /  위젯도 이 PC에서 실행
   → 방화벽·원격접속 설정이 전혀 필요 없습니다.


--------------------------------------------------------
 ★ 시작 전 — 데이터 백업 (중요)
--------------------------------------------------------
 이 PC에서 캘린더를 실사용 중이면 먼저 복사해 두세요.

     %APPDATA%\TaskCalendar\data.xml

 (이 위젯은 기존 위젯과 같은 데이터를 씁니다.)


--------------------------------------------------------
 1단계 — 위젯 exe 복원
--------------------------------------------------------
   reassemble.cmd  더블클릭
   → TaskCalendarWidget.exe 생성 + SHA256 자동 검증
   ("무결성 OK" 가 보여야 정상)

 ※ GitHub 100MB 제한 때문에 2조각으로 나눠 올렸습니다.


--------------------------------------------------------
 2단계 — DB 구축  (폴더: db)
--------------------------------------------------------

 [A] taskmgr DB를 아직 안 만들었다 (처음)
   db\init-db.cmd  더블클릭하고 아래를 입력

     MySQL root 비밀번호 :  (setup.cmd 때 정한 값)
     앱 계정 비밀번호    :  taskmgr1234      ← 반드시 이 값!

   ※ 위젯 안에 taskmgr1234 로 박혀 있습니다. 다르면 접속 실패합니다.
   결과: taskmgr DB + customer/project 테이블(빈 구조) + taskmgr_app 계정

 [B] 이미 예전 버전으로 taskmgr를 만들어 발주처/과제를 넣던 중이다
   → 테이블을 다시 만들지 말 것!  db\migrate.cmd  더블클릭 (root 비번만 입력)

   이걸 하면(2단계가 한 번에 적용됩니다):
    [1] (발주처, 사업명) 유니크 제약이 풀려 구성품별 계약·연도별 갱신이 막히지
        않게 되고, 계약명/통상명칭이 NOT NULL('')로 정리됩니다.
    [2] 구분/상태가 ENUM → 코드테이블(section_code/status_code)로 바뀝니다.
        앱에서 구분·상태를 추가/이름변경/순서변경/숨김 할 수 있게 됩니다.
        + 과제에 '비고'(관리 화면 전용 메모) 컬럼이 추가됩니다.
        + 위젯 계정(taskmgr_app)에 코드테이블 권한도 함께 부여됩니다.
   · 데이터는 보존됩니다(발주처·과제 그대로). 여러 번 눌러도 안전(이미 됐으면 건너뜀).
   · ※ init-db.cmd 는 테이블을 DROP(재구축)하므로 데이터가 있으면 절대 쓰지 마세요.
   · root 계정을 안 쓰는 서버라면:  db\migrate.cmd -DbUser 관리자계정명


--------------------------------------------------------
 3단계 — 위젯 실행
--------------------------------------------------------
   1단계에서 만든 TaskCalendarWidget.exe 더블클릭
   (설치 불필요 · .NET 설치 불필요 — 자체포함)

   확인:
     과제 관리 → "공식 과제(DB)" 화면이 열리고
     "등록된 공식 과제가 없습니다" 로 보이면 → DB 연결 성공(데이터만 없음)
     "서버에 연결되지 않아…" 로 보이면 → 2단계 확인

--------------------------------------------------------
 3-1단계 — 관리자 인증 (편집하려면 1회)
--------------------------------------------------------
   ⋯ 더보기 → 설정 → 관리자 →  관리자 비밀번호  입력 후 [인증]

     관리자 비밀번호 :  admin1234

   인증하면 배지가 "· 관리자 모드 · 활성" 으로 바뀌고,
   이 PC에서는 앱을 다시 켜도 계속 유지됩니다.

 ※ 인증하지 않은 채로 편집을 누르면
   "관리자 인증 필요 — 설정 열기" 안내가 뜹니다(설정으로 보내줍니다).

 ※ 비밀번호 변경은 인증한 뒤에만 가능합니다.
   (설정 → 관리자 → "관리자 비밀번호 변경")
   비밀번호를 잊었으면 앱 데이터 폴더의 db-config.json 을 지우면
   위 기본값(admin1234)으로 되돌아갑니다.


--------------------------------------------------------
 4단계 — 과제 데이터 넣기
--------------------------------------------------------
 A) 위젯에서 직접
    과제 관리 → 발주처 관리로 발주처 추가 → 새 공식 과제 등록
    · 발주처 추가/이름변경은 '발주처 관리'에서만 합니다(편집 폼 안에서는 못 합니다).
    · 구분·상태 값을 늘리거나 이름·순서를 바꾸려면 '구분·상태 관리'에서.
      (이름을 바꾸면 그 값을 쓰던 과제 표기도 전부 자동으로 따라 바뀝니다)
    · '비고'는 관리 화면에서만 보이는 내부 메모입니다(캘린더·보고서엔 안 나옴).
    · 기존 개인 과제를 공식 과제에 연결하려면: 과제 관리 → 재연결 →
      과제마다 [공식 과제 선택…] → 검색·필터 팝업에서 고르면 됩니다.

 B) 내부망 LLM으로 대량 생성 (과제가 많을 때 권장)
    db\load-template.sql 의 규칙을 내부망 LLM에 주고
    db\schema-structure.sql 과 함께 "실제 과제로 INSERT SQL 생성" 요청 →

        "C:\mysql\bin\mysql" -u root -p taskmgr < 만든파일.sql

    (발주처 먼저 → 과제 순서, section/status는 정해진 값만,
     선진행은 날짜·상태 NULL, id/uid는 넣지 않음)


--------------------------------------------------------
 소스코드가 필요하면
--------------------------------------------------------
     git clone -b feat/db-app https://github.com/Peace-Min/task-calendar.git

 설계 결정은 db/ARCHITECTURE.md (ADR 목록), 계획은 db/ROADMAP.md.
 ※ main 브랜치에는 아직 병합하지 않았습니다(기존 사용자 무영향).

 설정값 요약
--------------------------------------------------------
   DB 주소        localhost:3306
   데이터베이스   taskmgr
   앱 계정        taskmgr_app  /  taskmgr1234
   관리자         admin        /  admin1234

 ※ 테스트용 값입니다. 인원이 늘거나 실서버로 이관할 때
   더 강한 값으로 바꾸고 위젯을 다시 빌드하세요.
